Configure a development experiment

Compare the unchanged base weights with current advice/v1, compact advice/v2, and compact advice/v2 with deterministic field interpretation. All arms receive the same decision-time inputs, source excerpts, field definitions and approved lessons. The compact arms also use shorter, question-focused instructions.

This experiment does not change the active adviser or create training examples. Keep frozen evaluation cases and later outcomes out of development requests. The default comparison makes three bounded local CPU requests; no GPU or external builder is used.

Optional lesson ablation makes four requests with compact v2 and field interpretation throughout: no lessons, all applied lessons, one selected relevant lesson, and one selected potentially irrelevant lesson. Only lesson context changes. Add lesson_ablation with relevant_id, relevant_rationale, irrelevant_id and irrelevant_rationale. These are experimental selections, not new approval or relevance labels. Existing lesson records are preserved.

Alternatively, add "decision_selection": true for three no-lessons requests: existing compact instructions, answer-first instructions, and decision-gated instructions. Only the system instructions differ; full inputs, interpreted facts, sources and schema remain identical. This tests prompt sensitivity, without an automatic decision gate or additional model stages. Choose one experiment at a time.

For question-focused context selection, use "context_selection": {"fields": ["field_name"], "rationale": "Why these fields suffice for this question.", "reviewed": true}. Three no-lessons requests compare full context, selected raw fields/definitions, and the same selection with typed interpretations. Select explicitly reviewed fields, including a necessary absent field. Focused views omit the general mission/decision definition and the full record repeated in case text. The unchanged compact system and full control's decoding schema apply throughout.

For a two-request decision-contract comparison, use decision_contract with the same fields/rationale/reviewed selection object instead. Both requests receive identical focused interpreted context, shared task instructions and generation parameters, with no lessons. Only compact advice versus decision-only decoding differs. The minimal label provides no advice, citations or explanation to assess; review its decision separately.

Values are exact strings or null. Confirm decision-time availability and review rules before submitting. Each rule names a field, integer/category kind, definition, unit, sentinel/unknown/category tokens, accessible citation_id and verbatim source_quote. Find citations through the Teach knowledge search. No definitions are inferred automatically.
